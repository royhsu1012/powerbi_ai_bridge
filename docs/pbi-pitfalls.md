# PBI 開發踩坑（DAX／M／報表檔／PowerShell）

> 這是 [CLAUDE.md](../CLAUDE.md) 的延伸，用到才讀：寫 DAX 或驗算查詢、請使用者改 M、直接寫報表檔、寫 PowerShell 產生器之前，先看相關段落。
> 資料保護、防毒相容與確認視窗的規矩一律以 CLAUDE.md 為準。

這些坑的共同點：**寫入回「成功」、畫面看起來正常，結果卻是錯的。** 所以每一條都寫了怎麼驗。

標記：✅ 已在本工具實測（附日期）；⚠️ 還沒在本工具實測 —— 照保守的方式用，實測過就改成 ✅。
部分條目參考另一份 PBI AI Bridge 分支的踩坑筆記（2026-10-21 版），逐條對照過本版的行為；不適用本版的列在最後。

## 一、DAX

### 1. VAR 名稱只能用 ASCII ✅ 2026-10-22

- **症狀**：寫入量值回成功，之後查詢報語法錯誤（據回報是**每一句**都報，訊息不會指出是哪個量值）。
- **原因**：VAR 是不加方括號的識別字，`VAR 視窗起點 = …` 在剖析時就失敗（實測：`Invalid token`，位置指向第一個中文字）；
  TOM 只存字串、不檢查語法，所以寫入不會報錯。
  量值、資料行的名稱可以用中文（它們包在方括號裡）。
- **做法**：VAR 一律用 ASCII（`_windowStart`、`m0`、`basis`）。
- **驗法**：寫完跑健檢（`Get-PbiOverview | Select-String 健檢`）；壞掉的量值會列出名稱與位置。

### 2. 寫入回「成功」不代表公式對 ✅ 實際發生過

- **症狀**：批次回「N 成功 / 0 失敗」，畫面上的數字卻是空的或錯的；Power BI 存檔時還可能把引用壞量值的欄位從視覺上拿掉。
- **原因**：寫入只存字串。常見的兩種錯：`IF` 的分支回傳資料表（DAX 的 IF 只能回純量）、
  把量值直接寫在 `CALCULATE` 的篩選引數裡（`'表'[欄] = [某量值]` 不合法）。
- **做法**：要回傳不同的資料表時，用篩選把不適用的那張篩成空的再合併；量值先放進 VAR，再拿 VAR 當篩選值。
- **驗法**：每批寫完都跑健檢，再用 `Invoke-Dax` 驗算數字，兩者都過才存檔。

### 3. `DIVIDE` 的分子是 BLANK 時，結果是 BLANK 不是 0 ✅ 2026-10-22

- **症狀**：達成率在「完全沒有實績」的月份整格消失，而那正是最該被看到的月份。
- **原因**：沒有任何列符合時 `SUM` 回 BLANK；`DIVIDE` 的第三個參數只管**分母**是 0／BLANK 的情況，管不到分子。
- **做法**：`IF(NOT ISBLANK(target), DIVIDE(actual + 0, target))` —— `+ 0` 讓零實績變成 0%，外層 `IF` 保留「沒有目標就不顯示」。
- **驗法**：`EVALUATE ROW("x", DIVIDE(BLANK(), 5))` 會回空白；`DIVIDE(BLANK(), 5, 0)` 也是空白，`DIVIDE(5, BLANK(), 0)` 才是 0。

### 4. `CALCULATE` 的布林條件會清掉同一欄的篩選 ✅ 2026-10-22

- **症狀**：量值「有時候跟著切片器動、有時候不會」；比率的分子會動、分母不動。
- **原因**：`CALCULATE(x, 表[狀態] = "A")` 等於 `CALCULATE(x, FILTER(ALL(表[狀態]), …))`：先把那一欄的篩選全部清掉。
  只有**同一欄**的切片器、頁面篩選、列軸會失效，其他欄照常，所以很難察覺。
- **做法**：除非就是要忽略那一欄的篩選，否則寫成 `KEEPFILTERS(表[狀態] = "A")`。
  相減的量值（`[母體] - [子集]`）補 `IF(ISBLANK([母體]), BLANK(), …)`，避免出現 `BLANK() - 8 = -8`。
- **驗法**：把那一欄放進 `SUMMARIZECOLUMNS` 當列 —— 正確的結果是只有自己那一列有值；每一列都一樣就是中了。

### 5. `~` 在 `CONTAINSSTRING` 裡是跳脫字元；BLANK 比大小時當 0 ✅ 2026-10-22

- **症狀**：`CONTAINSSTRING(s, "~")` 對所有非空字串都回 TRUE；沒資料的列被算成「達標」。
- **原因**：`CONTAINSSTRING` 用萬用字元比對，`~` 用來跳脫 `?`、`*`。另外 `BLANK() <= 28` 在 DAX 是 TRUE。
- **做法**：找字面字元用 `FIND("~", s, 1, 0)`（找不到回 0）。拿可能為空的值跟門檻比之前，先明確排除空值。

### 6. 驗算查詢本身也會寫錯 ⚠️

- **症狀**：手算和量值對不上，差點去「修正」一個本來正確的量值。
- **原因**：`ADDCOLUMNS(SUMMARIZECOLUMNS(T[k], <篩選>), "x", [量值])` 裡的 `<篩選>` 只決定分組出哪些 `k`，
  外層的 `[量值]` 不在那個篩選裡。
- **做法**：把量值寫進 `SUMMARIZECOLUMNS` 本身（`SUMMARIZECOLUMNS(T[k], <篩選>, "x", [量值])`），
  或在外層用 `CALCULATE([量值], <同樣的篩選>)`。**對不上時先懷疑驗算查詢。**

### 7. 計算表對整數取百分位數會無聲失敗 ⚠️

- **症狀**：建計算表、重新整理、健檢都成功，但那張表**沒有任何資料行**，查詢報「找不到資料行」；同一段 DAX 用 `EVALUATE` 查卻正常。
- **原因**：計算表的定義裡，`MEDIAN`／`MEDIANX`／`PERCENTILEX.INC` 作用在整數上（整數欄、`INT()`、`DATEDIFF()`）。
- **做法**：先乘 `1.0` 轉成小數。
- **驗法**：建完計算表一定看資料行數：`((Get-PbiSchema).Tables | Where-Object Name -eq '<表>').Columns.Count`。
  不要為了驗證這條在使用者的模型上建測試用的計算表。

### 8. 累計（running total）慢在「每一格都重算」 ⚠️

- 成本和視覺上同時顯示的格數成正比：單一品項很快，全部列出就很慢。換掉 `ALLEXCEPT` 的寫法幾乎沒有差別。
- 軸是計算資料行（年／季／月）而不是日期欄本身時，用 `WINDOW` 改寫可能定位不到目前列，累計退化成當期值。
- **驗法**：用報表實際使用的那個軸重現，並檢查小計、總計格。只用日期軸比對可能全部通過，卻漏掉錯誤。

## 二、Power Query（M）

### 9. `Table.Distinct` 分大小寫，模型不分 ⚠️

- **症狀**：建關聯當下沒問題，某次重新整理後失敗：「資料行包含重複的值……」。
- **原因**：M 的 `Table.Distinct` 預設分大小寫；模型比對文字**不分大小寫、也不管尾端空白**，
  所以 `ABC-1` 與 `abc-1` 在 M 裡是兩列，進了模型變成重複的鍵。
- **做法**：要當關聯「一」端的鍵，去重時先 `Text.Trim`，再用 `Comparer.OrdinalIgnoreCase`。
- **驗法**：建關聯之前除了 `DISTINCTCOUNT = COUNTROWS`，也想想資料源將來會不會出現大小寫不同的寫法。

### 10. 使用者回「好了」不代表每段 M 都貼對了地方

- **症狀**：一次給兩段 M，使用者把 A 表的貼進 B 表；只檢查自己關心的數字，沒發現整張表的結構變了。
- **做法**：一次只請使用者改**一個**查詢。真的要改好幾個，每段 M 的第一行寫 `// 查詢：<名稱>`，說明裡用粗體標出查詢名稱。
- **驗法**：每張被改的表都用 `Compare-PbiTableProfile` 比對列數、欄位（見 `docs\power-query.md`）。

## 三、這套工具本身

### 11. 改量值名稱不會改到報表檔 ✅ 2026-10-22

- **症狀**：`Rename-PbiObject` 改名、存檔之後，用到那個量值的視覺變成錯誤方塊。
- **原因**：改名只改寫**模型裡**的 DAX 引用。報表檔（`visual.json`）用名稱指向量值，Power BI 存檔時不會幫你改 ——
  2026-10-22 實測：改名 6 個量值再存檔，磁碟上的 4 張表格仍然指著舊名稱。
- **做法**：改名之前先查哪些視覺用到它；改名、存檔之後照 `docs\pbip-report-editing.md` 的流程改報表檔。
- **驗法**：`Test-PbiReport`，`errorCount` 必須是 0（它會列出指向不存在欄位或量值的視覺）。

### 12. 資料保護會展開定義：下層定義有一處不合規，整句查詢都被擋 ✅ 2026-10-22

- `/api/query` 會一路展開被引用的量值、計算資料行、計算表的定義（回應會寫「已展開 N 筆量值定義」）。
  定義裡只要有一處被禁的寫法（例如 `UNION` 的引數直接放含受限欄位的變數），引用它的查詢就整句被擋，換彙總寫法也一樣。
- **做法**：改查不受影響的建構塊（量值引用的下層量值、資料表本身的總計）。
  只需要列數或相異值多寡時，白名單裡的儲存統計（`DISCOVER_STORAGE_TABLES` 的列數）也可以回答。
- **不要**用 `CONCATENATEX`、變數、中介量值把欄位藏起來繞過。真的需要時照 CLAUDE.md 用 `-AskUser` 問使用者。

### 13. 判斷某個欄位有沒有被用到，五個地方都要查

量值、計算資料行（與計算表）、關聯、排序依據（SortByColumn）、報表的視覺。只查量值就刪欄位，
視覺會變成錯誤方塊，關聯或排序會整個失效。

## 四、報表檔（PBIR）

> 流程與存檔順序見 `docs\pbip-report-editing.md`，這裡只記檔案格式的坑。

### 14. 照抄同一份報表既有視覺的寫法，不要憑記憶寫 ✅ 2026-10-22（格式）

- `objects`、`visualContainerObjects` 底下每個屬性的值都是**陣列**（本報表 374 個視覺全部如此）；
  寫成物件的話，據回報 Desktop 會默默丟掉整個視覺 ⚠️。
- 視覺類型名稱：堆疊直條圖是 `columnChart`、群組直條圖是 `clusteredColumnChart`、堆疊橫條圖是 `barChart`。
  寫錯名稱會被當成沒安裝的自訂視覺。
- 表格（`tableEx`）的欄位投影不要加 `"active": true`：據回報加了之後只顯示那一欄，量值欄會消失 ⚠️。
  矩陣（`pivotTable`）的列與欄帶 `active` 是正常的（標示展開到哪一層）—— 本報表 18 個矩陣都是這樣，11 個表格都沒有。
- **驗法**：寫完跑 `Test-PbiReport`；新的視覺類型第一次用時，請使用者接受變更後截圖確認。

### 15. 版面與互動的幾個坑 ⚠️

- 圖層由 `z` 值決定：底色的形狀要給最小的 `z`，否則會蓋住上面的標題與按鈕。
- 新頁面會吃到報表層級的篩選（`report.json` 的 `filterConfig`），寫新頁之前先看一眼。
- 不同維度表的切片器不會互相連動：在切片器加視覺層的量值篩選（`[計數] > 0`），不要為此開雙向關聯。

### 16. 能不截圖就不截圖 ✅ 2026-10-22

- 截圖最貴（token），而且**會把報表畫面上的資料直接送進 context，資料保護完全管不到** ——
  2026-10-22 一張截圖就帶進了切片器上的人名。
- 優先順序：模型 → 橋接 API；報表 → 讀寫報表檔（`Test-PbiReport` 查結構）；
  真的要看畫面時請使用者截圖或描述，自己截圖時縮小比例、只放大必要的區域，避開資料多的視覺。

## 五、PowerShell（寫產生器、驗算腳本時）

### 17. 只有一個元素的陣列會被攤開 ✅ 2026-10-22

- `return @($x)` 回傳的是 `$x` 本身；Windows PowerShell 5.1 的 `ConvertFrom-Json` 把整個 JSON 陣列當**一個**物件丟進管線，
  `@(… | ConvertFrom-Json).Count` 會是 1（2026-10-22 一份 18 個名字的清單就被數成 1）。
- **做法**：寫檔用 `ConvertTo-Json -InputObject @($x)`；讀回來接 `| ForEach-Object { $_ }` 展開；函式要回陣列時寫 `,@(…)`。

### 18. 變數名稱不分大小寫 ✅ 2026-10-22

- 參數 `$Ops` 和腳本裡的 `$ops` 是同一個變數，後者會把前者蓋掉（2026-10-22 一個陣列因此被改成字串）。
- **做法**：不同用途用不同的名字，不要用單一字母或只差大小寫的變數。

### 19. 函式名稱撞到內建別名 ⚠️

`FC`（Format-Custom）、`FL`、`FT`、`GC`、`CP`、`MP`…… 別名優先於函式，呼叫會默默跑去別名。函式一律用 `動詞-名詞` 的長名。

### 20. 雜湊表的鍵叫 `Values`、`Keys`、`Count` 時

`$h.Values` 拿到的是那個鍵的值，不是所有的值。要列舉請用 `$h.GetEnumerator()`。

### 21. 改檔腳本要能重跑、要能整批不寫

- 每一步先檢查是否已經做過；會失敗的檢查全部放在寫檔之前；所有內容在記憶體裡算好、檢查完，最後才一次寫出。
- 刪資料夾、寫索引檔（`pages.json`）、跑產生器拆成獨立的步驟，不要併成一個長指令 —— 中途逾時會留下指向不存在頁面的報表。
- 含中文的 `.ps1` 要存成 UTF-8 **含 BOM**（見 CLAUDE.md 的「編碼陷阱」）；Python 腳本含中文與反斜線時，用檔案工具寫成檔案再執行，不要用 heredoc。

## 不收的條目（對照過本版之後）

另一份分支的筆記裡，下列條目**不適用本版**：

| 條目 | 本版的狀況 |
|---|---|
| 改視覺用 `/api/inject-visual` 的注意事項 | 本版已移除這個端點（它會強制關閉並重開 Power BI，防毒的高危特徵） |
| M 經由 API 是唯讀的 | 本版可以用 `Set-PbiMQuery` 寫入，會跳確認視窗（見 `docs\power-query.md`） |
| Desktop 關著時直接改 TMDL 裡的 M | 會繞過 M 的確認視窗，本版不採用 |
| Desktop 不會偵測報表檔的外部變更 | 本版實測會跳「套用外部變更」（見 `docs\pbip-report-editing.md`） |
| `Save-PbiModel` 的 `fileChanged` 只看 `.pbip` | 本版看 `.Report` 與 `.SemanticModel`，並用 `-Expect` 確認內容 |
| 受限查詢用一次性權杖放行 | 本版用確認視窗（`-AskUser`） |
